# Issue #34 - CBR import QA

## Automated and native evidence

The product importer, typed error mapping, cleanup compensation, format
detection, and reuse of `ImageDirectoryImportPipeline` are covered by the
repository tests.

The Android native core was compiled with NDK 27.1.12297006 for
`armeabi-v7a`, `arm64-v8a`, `x86`, and `x86_64`. The pinned libarchive upstream
corpus was executed on an Android API 31 x86_64 emulator and produced the
expected outcomes:

| Case | Result |
| --- | --- |
| RAR4 valid | extracted |
| RAR4 corrupt | `ERR_CBR_CORRUPTED_ARCHIVE` |
| RAR4 encrypted | `ERR_CBR_ENCRYPTED_ARCHIVE` |
| RAR5 valid | extracted |
| RAR5 solid | extracted, `solid=true` |
| RAR5 corrupt | `ERR_CBR_CORRUPTED_ARCHIVE` |
| RAR5 encrypted | `ERR_CBR_ENCRYPTED_ARCHIVE` |
| RAR5 multi-volume | `ERR_CBR_MULTIVOLUME_UNSUPPORTED` |
| RAR5 symbolic link | `ERR_CBR_LINK_UNSUPPORTED` |

Traversal, absolute paths, dictionary size, entry size, total size, archive
size, and entry count are exercised by native boundary tests. The fixture
corpus is reproducible with:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify-cbr-native-android.ps1
powershell -ExecutionPolicy Bypass -File scripts/verify-cbr-fixtures-android.ps1
```

## Bounded-memory measurement

A RAR5 solid archive generated by official RAR 7.23 with a 64 MiB dictionary
contained 256 entries and produced 276,916,480 bytes on disk. The x86_64 native
runner on the API 31 emulator reported:

```text
OK entries=256 files=256 bytes=276916480 solid=true peakRssKb=69368
elapsedMs=982
```

The 67.7 MiB peak RSS is close to the configured 64 MiB dictionary and does not
grow with the complete 264.1 MiB decompressed output. This validates the native
extraction boundary, not the full application lifecycle on a physical device.

## Required physical Android QA

Build a development client containing `ReebbonCbr`, install it on the target
device, and use representative image-only CBR files for RAR4, RAR5, and RAR5
solid. Before each run:

```powershell
adb logcat -c
adb logcat -v threadtime ReebbonCbrMemory:I ReactNativeJS:I *:S
```

In a second terminal, capture memory at library idle, before picker, after
picker, during native acquisition/extraction, during the Images pipeline, and
after return to the library:

```powershell
adb shell dumpsys meminfo com.bakerscript.reebbon
```

Verify successful import, natural page order, first-page cover, reading, no JS
or UI-thread ANR, bounded native PSS/RSS, and removal of the private temporary
job directory. Repeat with corrupt, encrypted, multi-volume, traversal/link,
and over-limit archives. Also background/cancel the picker and kill the app
during extraction, then confirm that a later cleanup/import is possible.

## iOS status

No macOS/Xcode or physical iOS environment was available. The shared core and
Apple module are autolinked by Expo, but compilation and device behavior are not
claimed as validated. Run the commands in `modules/reebbon-cbr/README.md`, then
execute the same nominal/error corpus and inspect temporary-file cleanup and
memory on a physical iOS device before release.
